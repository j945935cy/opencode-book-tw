# 第 22 章：問題排除

每個工具都會有鬧脾氣的一天。這章是全書的救急包：高頻問題快速診斷表、日誌查看方法，以及求助管道。

## 22.1 常見錯誤診斷表

| 症狀 | 最可能原因 | 處置 |
|------|-----------|------|
| `command not found` | 執行檔不在 PATH | 重開終端機；npm 安裝者檢查全域 bin 路徑 |
| 啟動卡在載入畫面 | 供應商連線失敗 | 查網路與金鑰；`opencode providers` 看狀態 |
| 回覆中途斷線 | API 不穩或上下文過長 | 重試；長會話改開新會話（第 20 章） |
| TUI 圖示變方框 | 未用 Nerd Font | 安裝並選用（第 6 章） |
| 改動沒套用或改錯處 | 串到舊脈絡 | `/sessions` 確認所在會話，重看 diff |
| MCP 工具不出現 | 未啟用或啟動失敗 | `opencode mcp list`＋`/status`＋`mcp debug` |
| LSP 沒反應 | 伺服器未裝好或索引中 | `/status` 看就緒；大型專案等索引完成 |
| 設定改了沒生效 | 被更高層覆蓋 | 對照七層優先序排查（第 12 章） |

## 22.2 日誌與診斷工具

**日誌位置**

```bash
ls ~/.local/share/opencode/log/
```

目錄內按時間存放執行日誌。需要回報問題時，附上「重現步驟＋對應時段的日誌」能大幅加快解答速度。

**提高日誌詳細度**

```bash
opencode --print-logs --log-level DEBUG
```

排障時把級別開到 DEBUG，正常使用記得關回去（輸出量大且略影響效能）。

**結構化檢查點**

- `/status`：TUI 內看 LSP／MCP／外掛的就緒狀態——八成「功能壞了」其實是某子系統沒起來。
- `opencode debug`：官方提供的診斷子命令集合。
- `opencode doctor`（若你的版本提供）：一次體檢環境常見問題。

## 22.3 社群資源

按效率排序的求助路線：

1. **GitHub Issues**：<https://github.com/anomalyco/opencode/issues>。先搜尋再發問——你遇到的問題多半有人遇過。發 issue 附上：版本號（`opencode --version`）、作業系統、最小重現步驟、相關日誌片段。
2. **Discord 社群**：官網入口進入，即時討論適合卡在半路的緊急問題；中文使用者請善用搜尋找到既有討論串。
3. **官方文件**：<https://opencode.ai/docs/>。設定類問題九成答案都在這裡。

**提問的藝術**

好的求助文就是一份好的除錯報告（第 17 章的症狀五件套直接套用）。附上 `/share` 生成的會話連結是最有效率的方式之一——回答者能看到完整過程而不是你的轉述。敏感專案不能分享時，先做脫敏的最小重現。

## 本章摘要 {.unnumbered .unlisted}

- 高頻問題先查表：PATH、供應商連線、字型、會話串接、MCP/LSP 就緒狀態、設定覆蓋。
- 日誌在 `~/.local/share/opencode/log/`，排障時以 DEBUG 級別重現。
- `/status` 是第一檢查點；GitHub Issues 先搜後問，求助文附版本、平台、重現步驟與日誌。
