# 第 1 章　八個擴充點總覽

前兩冊你一直在「用」OpenCode，上一冊你已經看過它的引擎室。這一冊換你坐上工作臺：從只會更換零件的人，變成會製造零件的人。本章先給你整座工坊的地圖——OpenCode 的擴充點一共八個，先知道有什麼、各管什麼，後面的章節才不會迷路。

本書延續系列鐵律：**只寫能驗證的事**。所有行為主張都在 opencode-ai 1.18.21 上驗證過；標記〔實測〕的內容在本書撰寫環境實際跑過，標記〔文件〕的內容出自官方文檔並附出處。

## 1.1 擴充光譜：從改一句話到寫一個套件

八個擴充點不是平行的，它們站在一條「介入深度」的光譜上：

| 擴充點 | 你寫什麼 | 放哪裡 | 介入深度 |
|--------|----------|--------|----------|
| 自訂指令 | Markdown 提示範本 | `.opencode/commands/*.md` | 只影響一次提示 |
| Agent Skills | SKILL.md 說明文件 | `.opencode/skills/<名>/` | 讓代理按需載入知識 |
| 代理設定 | agent frontmatter | `.opencode/agents/*.md` | 改變代理的能力與權限 |
| 主題 | JSON 色盤 | `.opencode/themes/*.json` | 只改外觀 |
| MCP 伺服器 | 設定檔條目＋外部程序 | `opencode.json` 的 `mcp` | 給模型新工具（進程級） |
| 自訂工具 | TS/JS 函式 | `.opencode/tools/*.ts` | 給模型新工具（函式級） |
| 外掛 | JS/TS 鉤子模組 | `.opencode/plugins/*.js` | 攔截並改寫核心行為 |
| SDK 整合 | 你的獨立程式 | 任何地方 | 從外部完全操控 |

前五個不需要真正的程式碼——Markdown、JSON 就夠。後三個才動手寫 TypeScript。光譜越深，力量越大，維護成本也越高。建造者的第一修養是：**選最淺的那一格**。

## 1.2 選型決策

面對需求時，依序問四個問題：

**第一問：你想改的是「提示」還是「行為」？**
想讓某類任務有一段固定的、可帶參數的提示，用自訂指令（第 4 章）。想讓代理自己判斷「現在該不該翻某份說明書」，用 Skills（第 5 章）。兩者都只是文字。

**第二問：你想給模型「新能力」還是「新規矩」？**
新能力——查資料庫、呼內部 API——優先考慮自訂工具（第 11 章）；若能力本身已是獨立服務，包成 MCP 伺服器（第二冊第 10 章教過使用端）。新規矩——禁止碰某些檔案、強制特定流程——用代理設定加權限（第 6 章），或需要程式邏輯時用外掛攔截鉤子（第 8 章）。

**第三問：改的東西長在介面上面上嗎？**
純配色用主題 JSON（第 13 章）；要加面板、對話框、快捷鍵，得寫 TUI 外掛（第 14 章）。

**第四問：你是要「改變 OpenCode」還是「驅使 OpenCode」？**
前者留在上面七格；後者是另一條路——你的程式透過 SDK（第 16 章）把 OpenCode 當成一顆可程式的引擎，排程、批次、儀表板都算這類。

## 1.3 一張圖記住分工

設定檔也是分工的。核心行為（供應商、MCP、外掛清單、權限）寫在 `opencode.json`；終端介面的偏好（主題、TUI 外掛）寫在 `tui.json`〔實測〕。本書撰寫環境的 `tui.json` 只有兩行——一個 `$schema` 和同一份外掛清單，因為那支外掛同時提供核心鉤子與介面元素。

目錄慣例也一致得近乎無聊：專案層放 `.opencode/<種類>/`，全域層放 `~/.config/opencode/<種類>/`。學會一個，等於學會八個的安裝位置。完整的路徑總表收在本書附錄 C。

## 1.4 本書怎麼帶你練

全書分五篇。第一篇（第 1–3 章）備妥工坊：環境、依賴、除錯管道。第二篇（第 4–6 章）玩轉零程式碼擴充——指令、Skills、代理客製，大多數人到這裡就夠用了。第三篇（第 7–12 章）進入程式碼層：外掛鉤子全覽、自訂工具、以及把自己的外掛發布到 npm。第四篇（第 13–15 章）改造介面：主題、TUI 外掛、通知音效。第五篇（第 16–20 章）跳出來，用 SDK 把 OpenCode 變成你系統裡的一顆引擎，最後談發布與生態。

每一章都遵守同一套體例：先講「這個擴充點解決什麼問題」，再給最小可用範例，然後才是完整規格與陷阱。範例都可以直接抄進你的 `.opencode/` 目錄跑。

## 本章摘要

- 八個擴充點按介入深度排列：指令、Skills、代理、主題、MCP、自訂工具、外掛、SDK
- 選型四問：改提示還是行為？給能力還是規矩？動不動介面？改變它還是驅使它？
- 專案層 `.opencode/<種類>/`、全域層 `~/.config/opencode/<種類>/` 是通用慣例
- 核心設定住 `opencode.json`，介面偏好住 `tui.json`
