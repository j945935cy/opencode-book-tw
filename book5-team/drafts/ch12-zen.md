# 第 12 章　Zen：官方模型閘道

團隊導入的第一個現實問題不是「會不會用」，而是「用哪家的模型、錢怎麼算」。OpenCode Zen 是官方給的答案：一份經過測試與驗證的模型清單，包裝成一個普通供應商。它是完全可選的——不用 Zen 照樣能用 OpenCode——但它解決的三個痛點值得每個團隊認識。

## 12.1 Zen 解決什麼問題

同一顆模型在不同供應商手上的表現可能天差地遠：參數設定不同、路由到的版本不同。透過第三方聚合器呼叫時，你甚至無法確定拿到的是不是該模型的最佳版本〔文件〕。

Zen 的做法三步〔文件〕：篩選出一批適合當編碼代理的模型；與供應商確認正確的服務方式；實際基準測試後才放進推薦清單。賣點不是「多」而是「驗證過」——按成本價轉售（只收處理費），且不鎖定：Zen 的模型也能給其他編碼代理用，OpenCode 也永遠歡迎任何其他供應商。

## 12.2 啟用三步

```text
1. 到 opencode.ai/auth 登入，綁定付款方式，複製 API key
2. TUI 內 /connect → 選 OpenCode Zen → 貼上 key
3. /models 查看推薦模型清單
```

之後 Zen 就像其他供應商一樣出現在選單裡。設定檔中的模型 ID 格式為 `opencode/<model-id>`，例如 `opencode/gpt-5.5`〔文件〕。本書撰寫環境的預設模型正是這個格式（opencode/nemotron-3-ultra-free）〔實測〕。

## 12.3 機制面：計費、額度與退役

**按量計費**：以每百萬 token 計價（輸入／輸出／快取讀寫分開），儲值餘額扣款。餘額低於 5 美元會自動儲值（預設 20 美元，金額可調也可關）〔文件〕。

**月度上限**：可為整個 workspace 和每位成員設月度用量上限〔文件〕。注意它與 auto-reload 的互動：上限到了就停，但自動儲值可能讓實際扣款超出上限——財務敏感的團隊兩者要一起規劃。

**模型會退役**：官方維護著一張退役時間表，舊模型到期下線〔文件〕。這是本冊反覆出現的主題在模型面的化身——CI 裡釘死的 model 字串要有人定期對照清單更新，否則某天 pipeline 集體報錯才知道模型已走。

**免費與隱形模型**：清單中有多款限時免費模型（含標記為 stealth 的實驗型號）。免費有代價：部分免費端點在試用期會收集資料改進模型、或僅供試用不得提交機密內容〔文件〕。用它們跑日常練習沒問題，公司機密專案請避開並詳讀各自的資料政策。

## 12.4 團隊功能

Zen 的 workspace（beta 期間免費）就是為本章讀者準備的〔文件〕：

| 功能 | 說明 |
|------|------|
| 角色分工 | Admin 管 model、成員、key、帳務；Member 只管自己的 key |
| 成員月度限額 | Admin 可逐人設定花費上限 |
| 模型存取控制 | 停用特定模型——呼叫直接報錯。適合排除有資料收集疑慮的選項 |
| 自備金鑰（BYOK） | OpenAI／Anthropic 用自家 key 直結供應商計費，其餘模型照走 Zen |

最後一項特別務實：公司已經簽了 Anthropic 合約？BYOK 讓 Claude 的流量走原有合約，長尾的其他模型照用 Zen——一套介面，兩種帳單。

## 12.5 隱私底稿

大多數模型遵循零留存政策、不用你的資料訓練〔文件〕。例外集中在部分免費模型（試用期收集回饋）與 OpenAI/Anthropic 官方 API 的 30 天請求留存。合規敏感的團隊把第 17 章 enterprise 政策與此處的 workspace 模型開關疊起來用——禁用的模型從源頭就叫不通。

## 本章摘要

- Zen＝驗證過的模型閘道：測試→與供應商校準→基準化，成本價出售、零鎖定
- 三步啟用：auth 頁取 key、TUI /connect、/models 看清單；ID 格式 opencode/<model-id>
- 四個機制：按量計費＋auto-reload、workspace 月度上限、模型退役表、免費模型的資料代價
- 團隊四功能：角色、個人限額、模型開關、BYOK
- 本書原則：清單與價格會過期，機制不會——怎麼查比背誦重要
