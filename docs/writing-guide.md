# 撰寫規範（Style Guide）

## 一、語言與用語

1. 全書使用**繁體中文（台灣正體）**，術語一律遵循 `glossary/terminology.md`。
2. **全書不使用 emoji 符號**（含書稿、大綱、圖表與封面文案）。強調語氣改用粗體標籤：`> **重點**：`、`> **注意**：`。
3. 中英混排規則：
   - 中文與英文／數字之間加半形空格：`OpenCode 安裝完成後有 3 種模式`
   - 專有名詞保留英文原文不硬譯：OpenCode、MCP、LSP、Token、Agent
   - 首次出現的專有名詞採「英文（中文譯名）」格式：Model Context Protocol（模型情境協定）
3. 標點使用全形標點；程式碼、指令、路徑內保持半形。

## 二、結構規範

| 層級 | 用途 | 格式 |
|------|------|------|
| H1 | 章標題 | 僅一個：`# 第 N 章：標題` |
| H2 | 節 | `## N.1 標題` |
| H3 | 小節／演練 | `### 標題` |
| 引用區 | 重點、注意事項 | `> **重點**：` / `> **注意**：` |

- 每章開頭必有：學習目標、預估時間
- 每章結尾必有：本章摘要、下章預告
- 實作步驟一律編號列表，每步驟附驗證方式

## 三、程式碼規範

1. 所有範例碼同步存放於 `samples/bookN/chNN/`，書中引用相對路徑。
2. 程式語言標註齊全：```bash、```typescript、```python …
3. 指令輸出若超過 5 行，僅節錄關鍵部分並以 `...` 標示省略。
4. 敏感資訊（API key 等）一律用 `<YOUR_API_KEY>` 佔位。

## 四、版本凍結

1. 撰寫期間鎖定 `docs/version-freeze.md` 記錄的 OpenCode 版本。
2. 書中所有截圖、輸出、行為描述以凍結版為準。
3. 版本升級需開 Issue 評估影響範圍，經負責人同意才更新凍結記錄。

## 五、截圖與圖表

### 5.1 視覺素材分層政策

依資訊性質選用素材，優先序如下：

| 層級 | 形式 | 適用 | 可版控 |
|------|------|------|--------|
| L1 | 真實截圖 | 僅「介面外觀與質感」本身是重點時（如封面、全書僅 2~3 張主視覺） | 否 |
| L2 | 文字模擬終端機（code block） | 指令、輸入輸出、TUI 操作示範 | 是 |
| L3 | Mermaid 圖 | 流程、決策、架構、時序 | 是 |

原則：**預設用 L2／L3**，L1 僅留給必要的主視覺。尚未取得真實截圖的位置，插入 `<!-- SCREENSHOT-PENDING: 描述 -->` 註解標記，排版前再決定補圖或定稿為文字。

### 5.2 規格

| 類型 | 格式 | 命名 |
|------|------|------|
| 終端截圖（L1） | PNG | chNN-figMM-描述.png |
| 架構圖（L3） | Mermaid 直接寫在 md 內 | —— |
| 流程圖原始檔 | assets/src/（如需匯出） | chNN-diagMM-描述.mmd |

若使用 L1：解析度統一 1920×1080、dark 主題、14pt 字型、無個人資訊。

## 六、Git 工作流

```
main            ← 已審核通過的通過的穩定稿
└── dev         ← 整合中的稿件
    └── feat/book1-ch03   ← 個人寫作分支（一章一分支）
```

- 提交訊息格式：`bookN: chNN 章節簡述（新增/修改/修正）`
  - 例：`book1: ch03 新增首次使用流程`
- PR 合併前需通過：技術審稿通過 + 術語檢查通過
