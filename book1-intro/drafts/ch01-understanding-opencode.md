## 1.1 什麼是 AI 程式輔助工具

先想像一個場景。

你接手了一個陌生專案，主管丟給你一句話：「把會員資料匯出的功能加上 CSV 格式支援，下週上線。」你打開專案，發現有三百多個檔案，完全不知道從哪裡看起。以前你得花一個下午翻程式碼、查文件、在搜尋引擎和論壇之間來回跳躍——現在，有一種工具可以讓你直接用自然語言問它：「這個專案是怎麼處理會員資料的？匯出功能在哪裡？」它不只回答你，還能自己翻遍整個專案找出答案，甚至直接幫你把功能寫好、測試跑過，再回報結果。

這就是 **AI 程式輔助工具（AI coding assistant）**在做的事。

### 從自動補全到代理：三個世代

AI 輔助寫程式不是新鮮事，但它的能力在短短幾年內經歷了三次躍進：

**第一代：自動補全（Autocomplete）**

代表作品是 GitHub Copilot 剛推出時的樣子。你打幾個字，它猜你下一行要寫什麼，像一個反應很快但沒有記性的助理。它很方便，但它只看到「你現在正在編輯的這個檔案」，不知道你的專案全貌，更不會主動做事。

**第二代：聊天問答（Chat）**

ChatGPT 問世後，工程師開始把程式碼貼到對話框裡問：「這段為什麼會出錯？」這一代的工具理解能力大幅提升，但有個根本限制：**它在你編輯器之外**。你得手動複製貼上，它看不到你的其他檔案，改完的程式碼也要你自己貼回去。

**第三代：代理（Agent）**

這是目前最新的形態，也是本書主角 OpenCode 所屬的世代。「代理」的意思是：你不只「問」它，而是「指派任務」給它。它會：

- 自己讀取專案裡的檔案（不用你複製貼上）
- 自己修改程式碼（改完你看得到每一行變更）
- 自己執行終端機指令（例如跑測試、安裝套件）
- 根據執行結果判斷下一步（測試失敗就自己除錯再試一次）

一句話描述差別：前兩代的工具是「你問它答」，代理則是「你說目標，它想辦法達成」。

> **重點**：本書提到的「代理循環」（Agentic Loop），就是讓工具能連續自主執行十幾二十個步驟的核心機制。入門階段你只需要知道有這回事，第三冊《架構解密》會帶你拆解到原始碼層級。

### OpenCode 是什麼

**OpenCode** 是一套開源的 AI 程式輔助代理，主要在終端機（Terminal）裡運作，同時也提供桌面應用程式與編輯器延伸模組。你可以把它想成：

> 一個住在你終端機裡、隨時待命的資深工程師同事。它讀得懂你的整個專案，聽得懂自然語言的指示，能動手改程式碼、執行指令，而且——它背後的「大腦」（語言模型）可以自由替換。

兩個關鍵詞值得現在先記起來：

- **TUI（Terminal User Interface，終端機使用者介面）**：OpenCode 的主要操作介面長在終端機裡，用鍵盤操作，畫面像下圖這樣是一個文字介面的對話視窗。
- **LLM（Large Language Model，大型語言模型）**：代理背後負責「思考」的 AI 模型。OpenCode 本身不包含模型，它是連接各種模型的「駕駛艙」——這正是它最大的賣點之一，下一節詳談。

## 1.2 OpenCode 的優勢與特色

市面上的 AI 程式輔助工具不少，OpenCode 憑什麼佔有一席之地？以下五個特色，按對新手的重要性排序。

### 特色一：開源，而且徹底

OpenCode 以 MIT 授權完整公開原始碼，GitHub 星標數超過 19 萬，是全球成長最快的開源開發工具之一。對使用者而言，「開源」不只是理念口號，而是三個實際好處：

1. **免費使用工具本身**：你要付的只有背後模型的費用（而且有免費選項，見第五冊）。
2. **透明可審計**：它在做什麼、存取哪些檔案，程式碼攤在陽光下，企業資安部門查得起來。
3. **不怕公司倒掉**：即使原開發團隊停止維護，社群也能接手繼續發展。

### 特色二：不被任何一家模型廠商綁死

這是 OpenCode 與 Claude Code、Gemini CLI 這類官方工具最根本的差異。

Claude Code 只能用 Anthropic 的模型；Gemini CLI 只能用 Google 的模型。而 OpenCode 透過 Models.dev 目錄支援超過 75 家模型供應商——Anthropic、OpenAI、Google、xAI、DeepSeek，乃至於跑在自己電腦上的本地模型（如透過 Ollama 載入的開源權重），全部可以在同一套介面裡切換。

實務上這代表三件事：

| 你的需求 | 對應做法 |
|----------|----------|
| 今天想試試最新發表的模型 | 改一行設定就能換 |
| 不同任務用不同模型省錢 | 簡單修改交給便宜模型，關鍵決策交給旗艦模型 |
| 公司程式碼不能出門 | 換成本地模型，資料完全不經過外部 |

> **注意**：模型供應商的政策可能變動（歷史上確實發生過平台封鎖第三方工具存取的事件）。把雞蛋放在「多模型」的籃子裡，正是分散這類風險最好的方式。

### 特色三：三種形態，終端機優先

OpenCode 提供三種使用形態，共用同一套核心：

1. **TUI（終端機介面）**——本書的主軸。啟動快、資源省、在任何一台 SSH 連上的伺服器上都能用。
2. **桌面應用程式**——提供圖形化介面的版本，適合不習慣終端機的人。
3. **IDE 延伸模組**——整合進 VS Code、Cursor 等編輯器，也支援 JetBrains 系列、Neovim、Emacs 等透過 ACP 協定串接的環境。

本書聚焦 TUI，因為它是功能最完整、也是最能發揮代理威力的形態。別緊張——你不需要是終端機高手，第 2 章會手把手帶你把環境弄好。

### 特色四：隱私優先設計

OpenCode 的開發團隊明確宣示：**工具本身不會儲存你的程式碼與對話上下文**。所有資料預設只存在你自己的電腦裡（SQLite 資料庫），對話分享是完全手動的——你不執行 `/share`，就不會有任何東西離開你的機器。

對於處理客戶資料、營業秘密或有合規要求的讀者，這一點搭配「本地模型」選項，可以做到整條鏈路資料不出門。

### 特色五：免費上路是真的

很多工具號稱有免費方案，實際用兩天就撞牆。OpenCode 的零元路線是玩真的：

- **本地模型**：用 Ollama 在自己電腦上跑開源模型，一分錢都不用花（需要一張還可以的顯示卡或夠大的記憶體）。
- **免費額度**：部分供應商提供免費的 API 額度或免費模型，足以完成日常中小型任務。

具體怎麼組合出「每月 0 到 10 美元」的工作環境，第五冊《The OpenCode Stack》會用十個實際專案帶你走一遍。

### 一句話總結定位

如果要用一句話向同事介紹 OpenCode：

> 「它是一套開源、不綁模型廠商、以終端機為主的 AI 程式代理，工具本身免費，隱私可控，而且今天就能裝起來用。」

## 1.3 安裝前準備工作

第 2 章就要動手安裝了。這一節先把三件前置事項確認清楚，讓你到時候一次成功。

### 準備一：確認你的作業系統環境

OpenCode 支援三大平台，但建議程度不同：

| 平台 | 支援度 | 說明 |
|------|--------|------|
| macOS | 最佳 | 原生支援，Homebrew 一行搞定 |
| Linux | 最佳 | 原生支援，各發行版都有對應安裝方式 |
| Windows | 可用 | 強烈建議透過 WSL2（Windows Subsystem for Linux）執行，相容性與效能最好 |

如果你的電腦是 Windows：請先確認已安裝 WSL2 並建立 Ubuntu 子系統。還沒裝的話，微軟官方只需一行 PowerShell 指令 `wsl --install`，過程約十分鐘，第 2 章會附上逐步截圖。

> **硬體門檻**：執行 OpenCode 本身非常輕量（它只是個連網的客戶端）。唯一吃硬體的是「本地模型」選項——那需要 16GB 以上記憶體，或一張 8GB 顯示記憶體以上的顯示卡。若你打算全程使用雲端模型，一般辦公筆電即可。

### 準備二：挑一支現代終端機

OpenCode 的 TUI 使用了較新的終端機繪圖技術，建議使用近年的「GPU 加速終端機」，顯示效果與捲動順暢度會好非常多：

| 終端機 | 支援平台 | 特點 |
|--------|----------|------|
| WezTerm | 全平台 | 功能完整，跨平台一致性好（本書截圖採用） |
| Ghostty | macOS / Linux | 新秀，速度快，設定簡潔 |
| Kitty | macOS / Linux | 老牌高效能選擇 |
| Alacritty | 全平台 | 極簡主義，資源占用最低 |

Windows 使用者透過 WSL 搭配 Windows Terminal 也可以運作，但體驗以 WezTerm 為佳。

macOS 內建的「終端機.app」勉強可用但不建議；iTerm2 屬於堪用的中間地帶。總之：**能裝上面表格其中一支，就裝**。

### 準備三：搞懂 API 金鑰（API Key）

這是新手最容易卡關、也最容易出事的一環，值得花三分鐘建立正確觀念。

**API 金鑰是什麼？**

前面說過，OpenCode 是「駕駛艙」，模型才是「大腦」。而大腦住在供應商的雲端伺服器上，你的 OpenCode 要連上去使用，需要出示一組證件——那就是 API 金鑰：一串類似 `sk-ant-api03-Xj2K...` 的長字串。

**金鑰的兩個特性，決定了它的安全規則：**

1. 它等同一把付費鑰匙——任何人拿到它，就能用你的額度。
2. 它無法「掛失凍結」得那麼即時——外洩後的最佳處理是立刻在供應商後台刪除重建。

因此請牢記三條紀律：

- 禁止把金鑰貼進任何程式碼、截圖、貼文、聊天訊息
- 禁止把金鑰提交進 Git 版本庫（哪怕只是私有 repo）
- 務必將金鑰只放在 OpenCode 的設定流程裡（第 3 章的 `/connect` 會引導你安全存放）

**要去哪裡申請？**

取決於你想先用哪家模型。本書建議的路線：

1. **最快上手**：使用 OpenCode 官方的 Zen 服務（第 3 章 `/connect` 流程會帶你完成），一份金鑰即可使用官方精選驗證過的模型。
2. **想用特定大廠**：直接到該廠開發者後台申請（如 Anthropic Console、OpenAI Platform、Google AI Studio）。
3. **完全不想申請任何帳號**：走 Ollama 本地模型路線（第 3 章附錄 B 有快速指引，深入玩法見第五冊）。

不知道怎麼選？跟著本書走：**先用路線 1 上手，之後再依需求調整**。

### 檢查清單：進入第 2 章之前

```
□ 我知道 OpenCode 是「代理」，不是聊天機器人
□ 我的作業系統是 macOS / Linux，或 Windows 已準備好 WSL2
□ 我已挑好並安裝一支現代終端機
□ 我了解 API 金鑰的三條安全紀律
□ 我決定好了金鑰路線（Zen 快速上手／大廠後台／本地模型）
```

五項都打勾了嗎？那我們翻頁，五分鐘後你就會有一個能用的 OpenCode。
