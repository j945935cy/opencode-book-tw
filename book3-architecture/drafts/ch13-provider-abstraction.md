# 第 13 章　供應商抽象層

OpenCode 支援 75+ 供應商，從 Anthropic 到本地 Ollama。這一章拆解統一背後的抽象：模型 ID 的二元組語意、設定如何覆寫行為、以及免費與本地端點的接入差異。

## 13.1 一個介面、多個後端

第二冊附錄 D 比較過供應商；架構視角只問一個問題：**上層程式怎麼對「幾十種脾氣不同的 API」說同一種話？**

答案是經典的轉接器模式：核心定義統一的語言模型介面（串流、工具呼叫、用量回報），每個供應商一個轉接器把自家方言翻譯過來。官方 SDK 型別由 OpenAPI 規格生成，供應商清單則可程式化查詢：

```bash
curl -s http://127.0.0.1:4096/provider | python3 -m json.tool
```

回傳三塊：全部可用供應商、預設推薦、當前已連線清單。`GET /config/providers` 則是從設定角度的另一視圖。

## 13.2 模型 ID：二元組

書中反覆出現的 `anthropic/claude-xxx` 寫法是精確的架構語彙：**provider/model 二元組**。斜線前半選轉接器，後半選該轉接器下的一個模型。

這個設計讓「換模型」成純設定問題——會話表裡的 `agent`、`model` 欄位存的就是這種字串（第 5 章）。代理層釘模型、會話級切換，都是改一個字串的事。

## 13.3 三類端點的接入差異

| 類型 | 範例 | 接入要點 |
|------|------|----------|
| 雲端商業 | Anthropic、OpenAI | OAuth 或金鑰入 auth.json |
| 免費/代理 | 各家免費檔 | 同上，額度與限速不同 |
| 本地 | Ollama（localhost:11434/v1）、vLLM | 以相容端點自訂 provider |

本機真實設定就是第三類的活例子——以 OpenAI 相容協議指向本地推理服務。含義：**只要能講 OpenAI 方言，任何推理後端都能被收編**。

## 13.4 抽象層的代價

誠實記錄統一介面的兩個折衷：

- **獨家能力被拉齊**：某家的特殊功能若不在公共介面上，就用不到
- **方言差異殘留**：快取計費、reasoning token 的細節仍在用量欄位裡各有個性（第 5 章五欄位）

理解代價才能做對選型：追求穩定用主流雲端，追求隱私用本地，追求嘗鮮接受相容性風險。

## 本章摘要 {.unnumbered .unlisted}

- 轉接器模式統一 75+ 後端；/provider 端點讓清單可程式化。
- provider/model 二元組貫穿設定、會話與 API。
- 本地端點靠 OpenAI 相容協議接入。
- 抽象的代價：獨家能力拉齊、方言差異殘留在用量欄位。
