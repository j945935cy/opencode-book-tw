# 第 21 章：安全與隱私

給 AI 工具的權限，本質上是把一部分系統控制權交出去。這章把前面散落各章的安全話題收攏成一份完整的防護清單：權限設計的成熟做法、資料不出門的部署選項，以及從真實安全事件中提煉的教訓。

## 21.1 權限系統最佳實踐

第 3 章講了 allow／ask／deny 的機制；這裡給出經過實戰校準的基準設定：

```json
{
  "permission": {
    "edit": "allow",
    "webfetch": "allow",
    "bash": {
      "git status": "allow",
      "git diff*": "allow",
      "git log*": "allow",
      "npm test": "allow",
      "make test*": "allow",
      "git push*": "ask",
      "rm -rf *": "deny",
      "*": "ask"
    }
  }
}
```

設計邏輯：**唯讀與測試放行、有對外效果的要問、毀滅性的一律拒絕**。

五條進階守則：

1. **deny 清單優先維護。** `rm -rf`、`git reset --hard`、`DROP TABLE`、生產環境的 kubectl——先把你最承受不起的操作釘死。
2. **專案層收緊、個人層放寬是錯的方向**；正確方向永遠是團隊底線在專案層、個人在全域為自己加嚴（第 12 章合併規則決定了專案層贏）。
3. **定期演練 ask 提示的疲勞度**。如果團隊開始習慣性無腦按同意，代表 allow 清單該擴充了——確認疲勞比假裝安全有效。
4. **CI 與自動化場景用最小權限原則另立設定**，不要複用人機互動的設定檔。
5. **審查代理的行為報告是日常動作**，不是出事後的動作。TUI 的工具呼叫紀錄就是你的行為稽核軌跡。

## 21.2 本地模型與資料不出門方案

第 19 章講了分級策略；這節補部署細節。

**端點選擇**

| 方案 | 特點 | 適合 |
|------|------|------|
| Ollama | 安裝簡單、模型庫豐富 | 個人與小團隊入門 |
| vLLM | 高吞吐、生產級 | 內網正式服務 |
| LM Studio | 圖形介面、易於實驗 | 桌面試玩 |

OpenCode 以 OpenAI 相容介面接任何本地端點（第 19 章的 provider 範例），切換成本趨近於零。

**現實的能力預期**

截至撰寫時，本地開源模型在「讀懂大型程式碼庫並做多檔協調修改」這類任務上，仍明顯落後雲端旗艦模型。合理的期待排序：問答與解釋尚可、單檔小修堪用、多檔重構吃力、自主完成複雜功能不切實際。

務實心法：**敏感資料走本地、一般任務走雲端**的分級路由（第 19 章），比全盤本地化更符合大多數組織的風險與效率平衡。

## 21.3 已知 CVE 教訓

真實案例比原則更有教育意義。OpenCode 曾處理過一個值得每個使用者理解的安全議題：早期版本的本地 HTTP 伺服器認證不足。

**事件輪廓**

主從式架構意味著 OpenCode 會在本機開啟 HTTP 服務埠（第 2 章）。若該服務缺少足夠的存取驗證，理論上同一台機器上的惡意行程（或特定條件下跨來源的網頁請求）可能未經授權操作代理——而代理手上有你授予的工具權限。相關問題在社群回報後已修補並隨版本更新發布。

**三層教訓**

1. **保持更新是最便宜的安全措施。** `opencode upgrade` 一分鐘的事；CVE 公告值得訂閱（GitHub 的 Security Advisories）。
2. **繫結位址要保守。** `serve --hostname` 預設 127.0.0.1 有其道理；需要遠端存取時，用 SSH 隧道或 VPN 包住，不要直接裸奔 0.0.0.0 到不可信網路。
3. **權限系統是縱深防禦的最後一道**。就算伺服器被未授權存取，第 3 章的 deny 規則仍然攔得住毀滅性指令——這就是為什麼 deny 清單值得認真維護，而不是裝飾品。

通用化的心法：任何「AI 代理＋工具執行」的系統，攻擊面都等於其整合面的總和（HTTP 埠＋MCP 伺服器＋外掛）。每加一個整合點，就重新審一次它的認證與授權。

## 本章摘要 {.unnumbered .unlisted}

- 權限基準：唯讀與測試放行、對外效果要問、毀滅性拒絕；deny 清單最先維護，ask 疲勞是擴充 allow 的訊號而非關閉安全的理由。
- 本地端點（Ollama／vLLM／LM Studio）以 OpenAI 相容介面即插即用；能力預期要務實，「敏感走本地、一般走雲端」是平衡點。
- 從伺服器認證 CVE 學到的三件事：勤更新、保守繫結位址、deny 規則是縱深防禦的最後一道。
- 攻擊面等於整合面總和：每加一個 MCP 或外掛就重審一次認證。
