# 第 4 章　分享機制：一條連結的責任

「你把那個會話給我看看」——過去這句話意味著截圖或複製貼上。OpenCode 的分享機制把它變成一條 URL：`opncd.ai/s/<share-id>`，打開就是完整對話。但便利的背面寫著一行小字：**知道連結的任何人都能看**。這一章教你把這個機制用得又快又安全。

## 4.1 運作原理

執行分享時 OpenCode 做三件事〔文件〕：為會話產生唯一公開 URL、把對話歷史同步到官方伺服器、讓該連結可存取——內容包含**完整歷史、所有訊息與回應、會話中繼資料**。

第三冊第 5 章你看過 session 表的 `share_url` 欄位：分享狀態不是外掛魔法，是資料庫裡的一行記錄加一份同步副本。SDK 對應方法是 `session.share()`／`unshare()`（第四冊附錄 B）。

## 4.2 三種模式

設定檔的 `share` 欄位控制分享行為〔文件〕：

| 模式 | 行為 |
|------|------|
| `"manual"`（預設） | 不自動分享；需要時手動 `/share` 產生連結並複製到剪貼簿 |
| `"auto"` | 每個新會話自動分享並產生連結 |
| `"disabled"` | 完全停用分享 |

```json
{ "$schema": "https://opencode.ai/config.json", "share": "disabled" }
```

團隊策略很直接：預設 manual 已經夠好；要推廣「所有討論都有連結」的團隊開 auto 但要配教育；處理敏感代碼的專案——把 disabled 寫進專案層 opencode.json **並提交進 Git**，一行設定讓整個倉庫的所有人強制關閉分享〔文件〕。

## 4.3 收回：unshare

```
/unshare
```

停止分享並**刪除伺服器上的相關資料**〔文件〕。注意語意：不是「設為私密」而是真刪。協作結束後收回是基本禮儀，也是縮小暴露面的實際動作。GitHub 整合（第三篇）在公開倉庫預設自動分享會話——同一條紀律適用：PR 合併後順手 unshare 是好習慣。

## 4.4 隱私決策樹

按下 `/share` 之前走一遍：

1. 內容有金鑰、token、客戶資料嗎？→ 有：先清理（或用第四冊的外掛打碼）再說
2. 含專有代碼嗎？→ 公開連結等於發布，改用 export JSON 走內部管道（上一章）
3. 收件人需要的是「看」還是「接手」？→ 看用分享連結；接手用 import
4. 這個專案的 share 設定是什麼？→ disabled 的專案裡別想繞路

官方建議清單與此一致〔文件〕：只分享無敏感內容的會話、分享前審閱、協作完就 unshare、敏感專案整體停用。

## 4.5 企業選項預告

組織環境下分享功能可以整體停用（合規要求）、限定 SSO 登入者存取、甚至自架託管〔文件〕。細節在第 17 章 enterprise 展開；這裡先建立觀念：分享的三種模式是個人偏好，企業模式是治理決策，兩層不衝突——個人開 auto 也拗不過公司政策的 disabled。

## 本章摘要

- 分享＝同步全文到官方伺服器＋公開 URL（opncd.ai/s/），知道連結即可見
- 三模式：manual（預設）/auto/disabled；專案層 disabled 進版控即全隊強制
- /unshare 真刪伺服器資料，協作完必收
- 分享前四問：敏感內容？專有代碼？看或接手？專案政策？
- 企業可停用、限 SSO 或自架（第 17 章展開）
