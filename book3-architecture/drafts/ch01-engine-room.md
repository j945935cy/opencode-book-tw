# 第 1 章　為什麼要打開引擎室

你已經會用 OpenCode 了。第一冊教你安裝與第一次對話，第二冊給你實戰工作流。這一冊要做的只有一件事：把引擎蓋掀開，讓你看見裡面的每一根管線。

## 1.1 從「會用」到「懂它」的三種回報

**除錯的回報。** 當代理行為怪異——回應卡住、工具沒被呼叫、權限彈窗不出現——不懂架構的人只能重開軟體碰運氣；懂架構的人知道去看事件流、查資料表、翻日誌，三分鐘定位問題。

**客製的回報。** 想讓公司內部系統接上 OpenCode？想在自己的儀表板顯示每個專案的 token 花費？這些都需要繞過終端機介面，直接與核心對話。不理解架構，整合就無從下手。

**判斷的回報。** AI 工具更新飛快，宣傳話術滿天飛。理解一個系統真實的資料流向之後，你能一眼分辨「架構性能力」與「包裝話術」——這是技術選型最值錢的能力。

## 1.2 本書的方法論：只寫能驗證的事

談論 AI 工具內部最大的風險是想像力失控：「據說它用了某某技術」「大概是這樣運作的吧」。本書立下一條鐵律反制這種傾向：

> 書中每一個架構論述，都附帶一個你自己可以執行的驗證動作。

我們的證據來源有五類，全部來自你機器上就能觀察到的東西：

| 證據 | 驗證方式 |
|------|----------|
| 資料庫結構 | 唯讀查詢本地 SQLite |
| HTTP API | 官方 OpenAPI 規格＋curl 實測 |
| 檔案系統 | 走訪資料目錄、檢視實際檔案 |
| 日誌格式 | logfmt 逐欄解讀 |
| 官方文件 | 已驗證連結，逐條可點 |

凡是我們無法驗證的（例如原始碼層級的函數細節），本書明確標註「此為合理推斷」或乾脆不寫。你將學到的不只是 OpenCode 的架構，更是一套**審視任何 AI 工具的取證方法**。

撰寫基準版本為 v1.18.21。版本會老去，但方法不會。

## 1.3 全書地圖

五篇二十章，兩種讀法：

**應用型路線**（想用得更好）：第一篇 → 第四篇 → 第五篇。重點在 API 實戰與維運。

**整合型路線**（想把 OpenCode 接進自己的系統）：第二篇 → 第三篇 → 第四篇。重點在資料模型與協定。

各篇主題：

- **第一篇　全景篇**：client/server 分離設計、資料目錄地圖——建立整體心智模型
- **第二篇　核心引擎篇**：一次對話的完整旅程、20 張資料表、工具迴圈、權限體系
- **第三篇　周邊系統篇**：設定引擎、LSP、MCP、插件、快照復原、供應商抽象
- **第四篇　通訊篇**：HTTP Server、SSE 事件流、TUI 控制端點、ACP 協定層次
- **第五篇　維運洞察篇**：日誌解剖、效能容量、用規格追蹤演進

## 本章摘要 {.unnumbered .unlisted}

- 懂架構回報在三處：除錯速度、整合能力、選型判斷。
- 本書鐵律：每個論述都附帶可執行的驗證動作；不可驗證者明白標註。
- 五類證據：DB 結構、API 規格、檔案系統、日誌、官方文件。
