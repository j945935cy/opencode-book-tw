# 第 1 章　從 me 到 we：組織採用的四道關卡

一個人把 OpenCode 練到爐火純青，大約是一冊書的份量——你已經走完了。但「你很會用」和「你的團隊都在用」之間，隔著一整條工程化的峽谷：知識怎麼共享、機器怎麼自動化、供給怎麼穩定、行為怎麼治理。這一冊就是那條峽谷上的橋。

## 1.1 前情提要：你手上的四張地圖

快速盤點前四冊留給你的裝備，它們是本冊的前提：

- **第一冊《入門指南》**：安裝、第一次對話、基本介面操作
- **第二冊《實戰寶典》**：CLI 全命令、模式切換、MCP 使用、代理初寫
- **第三冊《架構解密》**：20 張資料表、Server API、SSE 事件流、logfmt 取證
- **第四冊《擴展開發》**：八個擴充點、17 支鉤子、SDK 自動化

本冊不重教這些；遇到舊概念時直接引用冊別章節。新登場的舞台只有一個方向：**讓 OpenCode 的價值從單人複製到群體**。

## 1.2 四道關卡

組織採用 AI 工具的過程，反覆出現同樣四個階段。本冊五篇正好逐一攻破：

**第一關：習慣資產化。** 個人的會話歷史、成本數據、工作流設定，原本散落在各處。第一篇（第 2–3 章）先教你把這些變成可管理、可遷移、可稽核的資產——安裝生命週期、會話匯出匯入、統計報表。

**第二關：成果可分享。** 「我用 AI 修好了」要能攤在同事面前驗證。第二篇（第 4–6 章）：分享連結、多裝置接管、瀏覽器 Web 介面——同一顆引擎，三種分享距離。

**第三關：平台自動化。** 這是本冊的重頭戲。第三篇（第 7–11 章）把 OpenCode 裝進 GitHub/GitLab：在 issue 留言 `/oc` 就有代理來解讀、開分支、提交 PR；排程任務每週巡檢代碼庫。AI 從「你問它答」升級為「駐守平台的隊友」。

**第四關：供給與治理。** 團隊規模一大，模型供給與行為約束就成為正經議題。第四篇（第 12–14 章）談 Zen 模型閘道、選型矩陣與網路受限環境；第五篇（第 15–20 章）收攏企業政策、內建工具全目錄、資料庫營運與 Windows/WSL 標準化。

## 1.3 本冊的新命令

前四冊你用過 run、serve、models；本冊主角是之前只在一旁待命的團隊向命令〔實測 `--help`〕：

| 命令 | 一句話定位 | 章 |
|------|-----------|----|
| `opencode stats` | token 用量與成本報表 | 3 |
| `opencode export` / `import` | 會話匯出／匯入 JSON | 3 |
| `opencode attach <url>` | 接管一台執行中的引擎 | 5 |
| `opencode web` | 啟動伺服器並開啟網頁介面 | 6 |
| `opencode github install/run` | 安裝與執行 GitHub 代理 | 7 |
| `opencode pr <number>` | 檢出 PR 分支並就地啟動 | 11 |
| `opencode db [query]` | 內建 sqlite3 shell 直查資料庫 | 18 |
| `opencode upgrade` / `uninstall` | 升級／解除安裝 | 2 |

## 1.4 本冊的方法論補丁

系列鐵律「只寫能驗證的事」在本冊遇到新挑戰：GitHub Actions 的行為跑在雲端 runner 上、Zen 的模型清單隨時間變動。應對方式有三：

- **能本地驗證的照舊實測**：所有 CLI 子命令的 help 與行為都在撰寫環境跑過
- **雲端行為引用官方文檔**：workflow YAML、事件表逐字核對 /docs/github（更新日期 2026-08-23）
- **時效性資訊只寫機制不寫快照**：例如 Zen 的可選模型會變，書中教「怎麼查」而非背誦清單

另外提醒：本冊大量涉及 GitHub 權限與金鑰。所有 secret 都走 GitHub Secrets 或環境變數，書中範例不含任何真實憑證——這條紅線第二冊立過，這裡再次生效。
