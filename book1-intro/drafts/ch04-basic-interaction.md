## 4.1 TUI 畫面導覽

OpenCode 的畫面結構很單純，認明四個區塊：

| 區塊 | 位置 | 用途 |
|------|------|------|
| 對話區 | 上方 | 你與代理的完整對話紀錄，含工具呼叫過程 |
| 輸入框 | 下方 | 打字的地方，Enter 送出 |
| 狀態列 | 底部邊緣 | 目前的模型名稱與模式（Build／Plan） |
| 快速鍵提示 | 畫面各處小字 | 常用操作的即時提醒 |

必備快速鍵先記這五個：

| 按鍵 | 作用 |
|------|------|
| Enter | 送出訊息 |
| Ctrl+C（兩次） | 離開 OpenCode |
| Esc | 中斷代理目前的執行 |
| Tab | 切換 Build／Plan 模式（下一章主角） |
| / | 輸入斜線開頭即可叫出指令 |

介面外觀可以換主題（`/themes` 指令挑選），本書截圖統一使用深色主題。

## 4.2 提問與回答

新手最常見的挫折不是工具不好用，而是「問法不對」。回憶第 3 章的心法——把代理當成剛報到的資深新人。具體來說，一個好的提問包含三個要素：

1. **目標**：你要什麼結果
2. **背景**：跟什麼有關、參考哪裡的做法
3. **範圍**：哪些檔案能動、哪些不能碰

比較看看：

```text
幫我修好登入的問題。
```

```text
使用者在登入時會被登出到首頁。
症狀：輸入正確帳密後短暫進入儀表板，一秒後跳回登入頁。
請先看 src/auth/ 下的登入流程，找出原因並提出修法，
先不要改程式碼。
```

第一種問法，代理只能猜；第二種問法，代理有明確的偵察路線與行為邊界（「先不要改」），來回一次就到位。

還有一個重要觀念：**對話是有記憶的，但記憶有容量**。同一個工作階段內，代理記得你說過的話；但話題切換很大時，開新會議比在舊會話裡硬繞更乾淨——舊上下文太多反而稀釋重點。

## 4.3 檔案引用：@語法

在輸入框打 `@`，會跳出專案檔案的模糊搜尋清單，繼續打字過濾、用方向鍵選取：

```text
@packages/functions/src/notes.ts 這個檔案裡的刪除功能是怎麼實作的？
```

@語法的價值是「指名道姓」。雖然代理通常自己找得到檔案，但你直接點名有三個好處：

- **省時間**：它不用花工具呼叫去搜尋
- **省額度**：搜尋也是要花模型 token 的
- **更精準**：避免它在同名或相似檔案之間猜錯

也可以引用整個資料夾：

```text`
@src/utils/ 這個資料夾裡有沒有重複功能的函式？
```

## 4.4 圖片上傳

OpenCode 能直接看圖。把圖片從檔案管理器**拖曳進終端機視窗**，路徑就會貼進輸入框，送出後代理會分析圖片內容。

三個實戰場景：

1. **錯誤對話窗截圖**：「像這張圖的錯誤，是哪段程式碼造成的？」
2. **設計稿比對**：「照這張設計稿把按鈕樣式調一致」
3. **架構白板照片**：「這張手繪的架構圖，幫我轉成對應的模組規劃」

> **注意**：終端機必須支援圖片路徑貼上。如果拖曳沒反應，直接把圖片的絕對路徑打進訊息裡也可以，代理同樣讀得到。

## 本章摘要

- TUI 四區塊：對話區、輸入框、狀態列、快速鍵提示；五個必備鍵：Enter、Ctrl+C、Esc、Tab、/。
- 好提問三要素：目標、背景、範圍。「先不要改程式碼」是偵察階段的關鍵句。
- @語法指名檔案或資料夾，省時間、省額度、防猜錯。
- 拖曳圖片可讓代理看懂截圖、設計稿與手繪圖。
